# 우리 버스 알림 v2.0

> v2.0은 주변정류소 API 호환 응답 처리, 버스번호별 다중 알림 저장, 시간 입력 겹침 개선을 포함합니다.


## v1.5 실시간 지도 개선

- 버스번호를 선택하면 공식 노선형상정보를 이용해 실제 노선을 지도에 표시합니다.
- 지도 기본값은 `전체 차량`이며 각 버스 마커에 노선번호와 차량번호 끝 4자리를 표시합니다.
- 도착정보 API가 일시적으로 실패해도 노선과 위치정보는 계속 표시합니다.
- 새로고침 버튼에 진행 상태와 완료 안내를 추가했습니다.
- `auth/configuration-not-found`가 발생해도 앱 전체가 중단되지 않고, 로컬 알림은 계속 동작합니다.
- 백그라운드 알림은 Firebase Authentication의 익명 로그인을 켜고 Functions·Firestore 규칙을 배포해야 합니다.


## 1.3.0 위치 표시 개선

- 실시간 지도 기본 범위를 `전체 노선`으로 변경
- 선택 노선에서 운행 중인 모든 차량을 지도에 표시
- 탑승 정류장 이전 접근 구간, 탑승 이동 구간, 목적지 이후 구간을 색상으로 구분
- `전체 노선 / 탑승 구간` 지도 전환 버튼 추가
- 브라우저 현재 위치를 이용한 반경 500m 주변 정류장 검색 추가
- 현재 위치와 위치 정확도 범위를 지도에 표시

현재 위치 검색은 HTTPS에서만 작동하며, iPhone/iPad/Android에서 브라우저 위치 권한을 허용해야 합니다.

# 우리 버스 알림

호계 e편한세상에서 평촌고·평촌학원가 방향으로 가는 버스를 찾아 실시간 위치를 표시하고, 설정한 시간대에 탑승 정류장 **3정거장 전**이 되면 푸시 알림을 보내는 설치형 PWA입니다.

## 구현 기능

- 경기도 공식 버스 API 정류장 검색
- 출발·도착 정류장을 함께 지나는 직행 노선 자동 탐색
- 노선 경유 정류장과 운행 중 차량 지도 표시
- 첫 번째·두 번째 버스 도착 예정시간 및 남은 정류장 수
- 요일·시간대·1~5정거장 전 알림 설정
- 앱 실행 중 30초 간격 자동 갱신 및 소리·진동 알림
- Firebase Cloud Functions 1분 감시 + FCM 백그라운드 푸시
- iPhone·Android 홈 화면 설치 지원

## 1. 공공데이터 API 키

공공데이터포털에서 아래 4개 API의 활용신청을 합니다. 개발계정은 자동승인됩니다.

1. 경기도_버스노선 조회
2. 경기도_정류소 조회
3. 경기도_버스위치정보 조회
4. 경기도_버스도착정보 조회

네 API를 모두 활용신청해야 합니다. **버스위치정보 조회만 승인받으면 정류장 검색 단계에서 403 오류가 발생합니다.** 같은 공공데이터포털 일반 인증키를 사용하며, Vercel에는 Encoding 키와 Decoding 키 중 어느 쪽을 넣어도 앱이 자동으로 정규화합니다.

```env
GBIS_SERVICE_KEY=발급받은_일반인증키
```


### 403 오류가 날 때

앱 첫 화면의 정류장 검색은 `경기도_정류소 조회` API를 사용합니다. 공공데이터포털 개발계정 상세보기에 `경기도_버스위치정보 조회`만 승인되어 있다면 파일을 다시 배포해도 403은 없어지지 않습니다. 아래 네 항목을 각각 활용신청한 뒤 Vercel에서 재배포하세요.

- 경기도_정류소 조회
- 경기도_버스노선 조회
- 경기도_버스위치정보 조회
- 경기도_버스도착정보 조회

수정 버전은 403 응답 시 어떤 API 승인이 빠졌는지 화면에 직접 표시합니다.

## 2. Firebase 설정

Firebase 콘솔에서 프로젝트를 만들고 다음 기능을 켭니다.

- Authentication → 익명 로그인 사용
- Firestore Database 생성
- Cloud Messaging → Web Push 인증서(VAPID 키) 생성
- 웹 앱 추가 후 Firebase 설정값 확인

Vercel 환경변수:

```env
FIREBASE_API_KEY=
FIREBASE_AUTH_DOMAIN=
FIREBASE_PROJECT_ID=
FIREBASE_STORAGE_BUCKET=
FIREBASE_MESSAGING_SENDER_ID=
FIREBASE_APP_ID=
FIREBASE_VAPID_KEY=
```

## 3. Vercel 배포

프로젝트 폴더를 GitHub에 올린 뒤 Vercel에서 Import합니다.

- Framework Preset: Other
- Build Command: 비워 둠
- Output Directory: 비워 둠
- 위 환경변수 8개 등록

## 4. Firebase Functions 배포

백그라운드 감시는 Cloud Scheduler를 쓰므로 Firebase Blaze 요금제가 필요합니다. 호출량은 알림 수와 감시 시간에 따라 달라집니다.

```bash
npm install -g firebase-tools
firebase login
cp .firebaserc.example .firebaserc
# .firebaserc의 프로젝트 ID 수정
cd functions
npm install
cd ..
firebase functions:secrets:set GBIS_SERVICE_KEY
firebase deploy --only functions,firestore:rules
```

Functions 비밀값에도 공공데이터 일반 인증키를 입력합니다.

## 5. 휴대폰 설치

### iPhone/iPad

Safari에서 배포 주소 열기 → 공유 → **홈 화면에 추가** → 설치된 앱을 열어 알림 허용.

### Android

Chrome에서 배포 주소 열기 → 메뉴 → **앱 설치** 또는 **홈 화면에 추가** → 알림 허용.

## 알림 동작 원리

경기도 도착정보의 `locationNo1` 값은 첫 번째 차량이 탑승 정류장으로부터 몇 정류장 전에 있는지를 뜻합니다. 서버가 매분 확인해 설정값 이하가 되는 순간 한 번 알리고, 해당 버스가 지나가 다음 버스가 멀어지면 다시 알림 대기 상태로 전환합니다.

## 주의사항

- 도착시간과 위치는 교통상황·운행정보 지연에 따라 실제와 차이가 날 수 있습니다.
- 휴대폰 무음 또는 방해금지 모드에서는 알림 소리가 제한될 수 있습니다.
- 앱 화면의 실시간 위치는 30초, 백그라운드 푸시는 1분 단위라 3정거장 진입 후 최대 약 1분 뒤 알릴 수 있습니다.
- 개발계정 API 호출량이 부족하면 공공데이터포털에서 운영계정 트래픽 증량을 신청해야 합니다.


## v1.6 위치·노선·오는 버스 개선

- iPhone/iPad에서 여러 위치 샘플 중 정확도가 높은 좌표를 선택합니다.
- 현재 좌표와 주변 8개 보조 좌표를 조회해 최대 1.1km 안 정류장을 가까운 순서로 표시합니다.
- 버스 선택 즉시 실제 노선 형상과 경유 정류소를 지도에 그립니다.
- 도착정보의 첫 번째·두 번째 차량을 위치 API와 병합해 오는 버스를 우선 표시합니다.
- 위치 API가 잠깐 비어도 최근 정상 차량정보를 최대 90초 유지하며 새로고침 요청을 다시 시작할 수 있습니다.


## v1.7 종점·회차 노선 오는 버스 판정 개선

- 정류장 도착정보 목록(`getBusArrivalListv2`)에서 선택한 노선과 실제 탑승 방향에 맞는 `staOrder`를 다시 확인합니다.
- `turnSeq`와 버스 위치의 `stationSeq`를 결합해, 6-1처럼 탑승 정류장이 노선 출발 종점인 경우 **회차점을 지나 종점으로 돌아오는 차량**을 오는 버스로 판정합니다.
- 공식 도착정보가 비어도 가장 가까운 운행 차량과 다음 차량을 위치 기준 남은 정류장 수로 표시합니다.
- 회차 후 접근 차량은 지도에서 청록색, 다음 회차 후보는 주황색으로 구분하고 노선번호·차량번호 끝자리를 함께 표시합니다.
- 화면을 열어둔 상태의 알림과 Firebase 예약 함수 모두 도착정보가 없을 때 버스위치정보를 보조 판정에 사용합니다.
- 패치 적용 후 기존 알림은 **알림 허용하고 저장**을 다시 눌러야 노선 최소·최대 순번과 회차정보가 Firestore에 갱신됩니다.

## v1.8 출발 정류장 기준 전체 노선 탐색

- 기존의 `출발 정류장 노선 ∩ 도착 정류장 노선` 단순 교집합 방식을 제거했습니다.
- 출발 정류장에 정차하는 모든 경기버스를 먼저 조회한 뒤, 각 노선의 공식 경유정류소 목록에서 도착 정류장이 출발 정류장보다 뒤에 있는지 직접 확인합니다.
- 같은 노선이 순환·회차·중복 정류소를 포함해도 실제 정류장 순번 조합 중 가장 가까운 직행 구간을 선택합니다.
- 정류소 ID가 드물게 다르게 내려오는 경우에만 동일 이름·25m 이내 좌표를 보조로 비교하며, 반대편 정류장은 섞지 않습니다.
- 노선 확인 진행률과 확인된 출발 노선 수·직행 노선 수를 화면에 표시합니다.
- 선택한 노선의 경유정류소 목록을 재사용해 버스 선택 후 노선 지도와 실시간 차량을 더 빠르게 표시합니다.

## v2.1 추가 기능

- 알림 저장 시 Firebase나 푸시 권한보다 먼저 브라우저 기기 저장소에 저장합니다.
- 푸시 서버 저장이 실패해도 버스번호별 로컬 알림은 유지됩니다.
- 알림 방식 4종: 소리·진동·푸시 / 소리·푸시 / 진동·푸시 / 푸시만
- 알림 소리 6종: 기본 / 경쾌 / 긴급 / 부드러움 / 차임 / 무음
- 도착 정류장 즐겨찾기 저장, 불러오기, 개별 삭제
- 서비스워커 캐시 버전 v2.1

배포 후 기존 홈 화면 앱이나 브라우저 탭을 완전히 종료한 뒤 다시 실행해야 새 서비스워커가 적용됩니다.

## v2.2 삭제 수정
버스번호별 저장 알림은 삭제 버튼을 누르는 즉시 기기에서 제거됩니다. Firebase 연결이 불안정해도 로컬 삭제가 우선 적용되며, 서버 문서는 뒤에서 삭제하거나 비활성화합니다.
